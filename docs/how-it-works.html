Swift Concurrency Auditor

Each time Claude edits a .swift file, the auditor checks it for data races, actor-isolation gaps and leaking tasks. Nothing is blocked. Claude gets a short note with the findings and can fix them in the same turn. You see the results on the status line, in a live pane with a Fix button for each finding, and in a Swift 6 readiness score.

What happens after an edit

  1. Claude editsEdit or Write on a .swift file
  2. Soft auditFast pattern checks run after the edit; nothing is blocked
  3. Note to ClaudeFindings with fix hints; the status line updates
  4. Pane and report/concurrency and /concurrency-report refresh
  5. FixA background agent fixes that one finding, without committing
  6. Re-auditCounted as fixed only once the finding is gone

A failed run leaves the finding in place and its button changes to Retry. The agent can only read and edit files, so it never commits or pushes.

Readiness score

How the score is calculated

The score starts at 100 and each open finding subtracts points by severity, down to a minimum of 0. Change the counts to see the effect. The starting counts match the screenshot in the README.

What it checks

Eight rules

The checks are fast pattern matches, not the compiler, so expect some false positives. Click a rule to see an example of code it flags and how to fix it.

To silence a rule on one line, add // audit:ignore CA014 on that line or the line above it.

Commands

/concurrency

Opens a live pane with the findings for every Swift file touched this session, a Fix button for each finding, and a list of finished fix runs. Esc closes it.

/concurrency-report

Writes the HTML dashboard to .concurrency-audit/report.html and shows a readiness card and severity tiles above the prompt.

/concurrency-audit path/File.swift

Audits any Swift file on demand. The pane, band and report update the same way.
